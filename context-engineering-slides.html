The Why

How Context Changes the Model2 min

The model is the same. The difference is whether repo rules arrive in the prompt by default or stay hidden behind a retrieval decision.

Key Insight
Passive context gives the agent commands, conventions, and constraints before it starts reasoning. Search and MCP still help, but only after the agent decides to use them.
Speaking Notes: "What changes the output isn't that the model gets a new brain. It gets better inputs. Parametric knowledge is still the base model — what it learned in training. But passive repo context means AGENTS.md and instruction files are already in the prompt before the agent starts reasoning. Search and MCP still matter for deeper lookup, but they're secondary because the agent has to decide to use them. When passive context and selective retrieval feed the same agent, it stops reasoning only from training priors and starts reasoning from the repository itself."
The Why

ETH Zürich — What They Actually Found1.5 min

The strongest public academic study found only modest task-success gains — but clear behavioral changes and higher cost.

Practical Takeaway
Minimal, developer-written context looks safer than auto-generated boilerplate. Keep the file lean and focused on non-obvious repo rules.
arXiv 2602.11988
Speaking Notes: "ETH Zürich ran the most rigorous public study so far: 138 tasks across 12 repositories with 4 different agents. This chart shows the headline result with no context normalized to 100. Developer-written context files improved task success by about 4% on average. LLM-generated context files made it slightly worse — about 3% down on average. But the nuance matters: context files still changed behavior. Agents explored more broadly, ran more tests, and increased reasoning effort, with over 20% higher inference cost. The practical takeaway is not that context files don't matter — it's that minimal, human-written context is safer than auto-generated boilerplate."
